## 工作方式

1. 先阅读仓库 `README.md` 与 `docs/` 下的开发约定，严格遵守代码与迁移约定（数据库迁移脚本放 `database/`，Java 在 `plm-backend/`，Vue 在 `plm-frontend/`）。
2. 定位问题根因或功能入口，做**最小改动**；不要重构无关代码，不要修改无关文件。
3. 如修复逻辑适合测试，请补充对应测试。
4. 修改后请自行运行与改动相关的最小验证命令（后端在 `plm-backend/` 下 `mvn -o -q test`、前端在 `plm-frontend/` 下 `npm run build`）。
5. **不要执行 git commit / git push**，提交由外部流程统一完成。
6. 禁止修改或读取 `.env`、`.env.local`、`scripts/deploy-*`、`docker-compose-prod.yml` 等部署与密钥文件。
7. 如果信息不足或无法定位问题，不要强行编造改动；直接在最终输出里说明「无法完成」及原因。

## 最终输出格式

在回答末尾给出：

1. 问题根因 / 需求实现思路；
2. 修改的文件清单与每个文件的改动要点；
3. 你运行过的验证命令与结果。

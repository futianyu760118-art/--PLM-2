# 01 范围与决策

## 1. 设计基线
- 五种模式：原版业务、产品工作空间、专业视图集、Teambition 参考项目协同、Multica 参考工作项视图。
- 模式切换时，项目编号、料号、任务状态与用户权限保持一致。
- 侧栏随模式改变信息分组与布局，不是只换颜色。
- 上位关系遵循 AEOS：研发中心展示跨岗位业务；岗位微系统集中于过去的报告、未来的待办。
- 全生命周期覆盖立项至退市及归档后的持续义务；不擅自重命名或映射 G0–G8。
- 教材、使用说明、学习进度与外观设置是前端交付组成部分。

## 2. 本期实施范围
保留现有 Vue 3 / Element Plus / Pinia / Vue Router / Axios / Three.js 技术基础。复用现有请求层、业务组件、接口、权限和状态枚举，调整布局、导航、页面聚合、说明与个人设置。

## 3. 明确禁止的实现方式
- 不把单文件原型直接替换生产前端。
- 不为五种模式分别复制业务状态、任务和权限逻辑。
- 不用隐藏按钮替代后端授权。
- 不在没有真实来源时显示测试合格、真实进度、Agent 执行成功或退市已完成。
- 不因“后端不变”而绕过后端缺失的业务约束；发现阻断必须登记并限缩入口。
- 不把模板式查询包装成已接入通用大模型。

## 4. 能力分层
| 类型 | 内容 | 处理要求 |
|---|---|---|
| 已读取源码存在 | 项目、阶段门、工作项、BOM、工作表、档案、模型查看、规则工具等 | 仍须在冻结提交上确认字段、返回格式和运行结果 |
| 可纯前端实现 | 模式、侧栏、卡片/列表/看板、说明、教材、阅读标记、外观 | 组件化实现并验证跨模式一致性 |
| 待后端核对 | 项目级角色、跨模块精准关联、阶段门校验、模型转换环境 | 未验证不开放写入或宣称完成 |
| 本期规划入口 | 上市在产、售后聚合、停产与退市执行、Agent runtime、Skills注册库 | 显示未接入与所需资料，不虚构接口 |

## 5. 阶段放行
设计原型可评审，不等于实施已完成。正式开发以 03 的接口矩阵和 04 任务结果为依据；发布以 05 验收为依据。本方案不包含后端修改；资料归档按用户后续明确指令推送至指定仓库。

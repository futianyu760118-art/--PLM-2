# 08 风险、交接与回退

## 风险登记
| 风险 | 当前情况 | 处置 |
|---|---|---|
| 真实浏览器不可用 | Chromium下载损坏，视觉验收缺失 | 发布前补齐，不能用Node检查替代 |
| CSS/函数层叠覆盖 | 单文件原型多轮叠加 | 正式Vue实现集中组件与主题token |
| 暗色误解 | 当前只有深色工作区和可选深色侧栏 | 明确不是完整暗色系统，逐页验证 |
| 五模式能力漂移 | 多页面容易漏同步 | 同一store/接口/表单，统一回归 |
| 后续生命周期数据缺失 | 停产/退市尚未确认接口 | 保留规划提示，不虚构执行能力 |
| 权限缺口 | 项目级授权与端点范围待验证 | 后端缺口是上线阻断，前端隐藏无效 |
| 本地草稿丢失 | 浏览器清理或跨设备不可共享 | 明确提醒，正式同步另行设计 |
| 原型被当成正式系统 | 示例人员/料号/金额均非实际记录 | 演示标识持续保留，迁移时移除fixtures |

## 开发交接清单
- 冻结仓库SHA与原版基线。
- 为任务清单填写人员姓名、实际时间和验收证据。
- 形成页面—组件—接口—权限矩阵。
- 完成五种界面的入口覆盖清单和窄屏方案。
- 提供主题迁移、学习进度与草稿保存策略。
- 提供构建结果、接口联调记录、浏览器验收记录。
- 明确已接入、仅演示、待后端支持三类能力。
- 教材与说明随最终实现更新。

## 发布与回退
先在测试环境并行保留原版与新模式。按角色验证后再决定默认模式。采用可回退的前端版本与路由，不改变生产数据库结构。发生误写、权限异常、任务不一致或主要页面失效时切回已验证前端版本，记录问题和影响。

## 本资料包不包含
生产后端修改、数据库迁移、真实Multica服务、真实退市审批、最终公司LOGO资产、完整浏览器测试截图、正式前端实现提交或部署。后续如需这些内容，应按独立范围执行。

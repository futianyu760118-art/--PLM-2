## 二、手工合并内容（patch 4 变化 + PLM 定制保留）

1. `handlerTimeoutMs()`：query 30s / reasoning 200s（支持 dispatch `timeoutMs` 覆盖）；
2. `handleDispatch()`：超时计时器 + `finish()` 释放 activeRun + 守卫式 sendComplete/sendFailed + 超时发 `run_failed(EXECUTION_TIMEOUT)` 并 `controller.abort()` 真正中断请求；
3. `handleRecall()`：清 timer + 保留 PLM 的 `controller.abort()`；
4. `heartbeat()` 携带 `currentRunId`（空闲显式 null）；`scheduleReconnect()` 清 activeRun timer。

**额外发现并修复的根因**：PLM 旧版在加 AbortSignal 修复时丢失了 `.then((result) => ctx.sendComplete(result))` 链——handler 执行成功但 **run_complete 从不上报**，这正是 Hub 派单一直卡在 `dispatched` 的直接原因。本次合并已恢复该链。

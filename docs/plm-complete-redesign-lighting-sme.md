# 工贸一体灯具企业完整 PLM 系统设计说明书

> **文档编号**: HJ-PLM-SME-V1.0-20260722  
> **适用画像**: 100–300 人 · 年销售额 0.5–2 亿人民币 · 工贸一体 · **偏重灯具制造**（投光/工矿/户外/商业照明等）  
> **设计依据**: PLM-2 底座、三维爆炸中台(:3000)、EBMS 经营平台(:3010)、生命周期缺口分析、EBMS×PLM 打通总规  
> **设计原则**: **够用、可落地、可分期**；不做世界 500 强级重型 PLM，但必须覆盖「接单→设计→模具→量产→变更→售后」全链受控。  
> **迭代**: 自动化/精益/自检/KPI-OKR/智能体 见 **[V1.1](./plm-complete-redesign-lighting-sme-v1.1.md)** + `database/10_v1_1_lean_agent_kpi.sql`

---

## 0. 一句话定义

> **以料号 PartNo 为唯一锚点，以项目/订单为经营拉通，以版本与 ECN 为变更心脏，以 BOM 三态 + 成本视图为制造与贸易桥梁，为 100–300 人灯具工贸企业提供「工程真相源 + 经营可算账」的完整 PLM。**


| 系统 | PLM 关系 |
|------|----------|
| **EBMS** | 经营跟进权威；消费 PLM 主数据/BOM/状态；回写项目号、订单锁版本 |
| **ERP** | 价/库存/采购收发权威；PLM 推送已发布料号与 MBOM |
| **CAD** | 设计工具；PLM 收结构与文件 |
| **MES**（若有） | 接收 MBOM/SOP；本阶段接口预留 |

### 2.3 技术选型（贴合规模）

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | Vue3 + Element Plus + Three.js + Pinia | 已有两套前端可合并 |
| 后端 | **Java 17 + Spring Boot 3 模块化单体** | 事务/RBAC/审计成熟；300 人内不必拆微服务 |
| 算法 | Python FastAPI + trimesh（+ 可选 OCCT） | 3D/AI |
| DB | PostgreSQL 15（ltree/JSONB） | 树与版本快照 |
| 缓存队列 | Redis | 会话、锁、任务、Outbox 消费 |
| 文件 | 本地/NAS 双目录（intranet/extranet） | 成本可控 |
| 部署 | Docker Compose 5 服务 | IT 2–6 人可运维 |
| 认证 | JWT + 本地账号；预留 LDAP/企业微信 | 分期 |

**不采用**: 重型 BPM、ESB、多套独立 PLM 库、SQLite 生产库、双后端（Java+.NET）长期并存。

## 3. 核心设计原则

1. **单一真相**: 工程属性、版本、图纸、ECN 只在 PLM。  
2. **单一状态**: `lifecycle_state` 唯一；`phase` 正交表示 NPI 阶段。  
3. **表驱动生命周期**: 转换矩阵 + 守卫 + 副作用；禁止随意 `changeStatus`。  
4. **发布必快照**: Part/BOM/关键文件版本 JSONB 落库。  
5. **变更必 ECN**: 已发布对象修改只能走 ECR→ECN。  
6. **经营可算**: 任何正式 BOM 可输出 **成本视图 CBOM** 给 EBMS。  
7. **灯具模板优先**: 档案目录、检验分类、爆炸模板、配置项预置灯具行业包。  
8. **小步上线**: 8 个波浪交付，每波可独立产生管理价值。

## 4. 统一领域模型

### 4.1 主数据 `plm_part`（物料/产品一体）

| 字段组 | 关键字段 | 说明 |
|--------|----------|------|
| 标识 | part_no PK、name_zh、name_en | 全球唯一料号 |
| 分类 | part_category、product_type、material_class | PRODUCT/ASSEMBLY/COMPONENT/STANDARD/PACKAGING；灯具品类 |
| 版本 | revision、version_no | 显示版次 + 规范版本 V1.0 |
| 状态 | lifecycle_state、phase | 见 §5 |
| 灯具属性 | ip_rating、power_w、cct、beam_angle、input_voltage、optical_type、housing_material | 成品/关键件 |
| 贸易 | hs_code、net_weight、gross_weight、carton_qty | 外贸 |
| 协同 | owner_id、project_no、customer_code | 项目/客户 |
| 3D | model_3d_path、template_id | 爆炸模板 |

**参数表** `plm_part_param`（版本化）: 材质、RoHS、供应商、检验规范、MOQ、参考成本…  

**编码建议（灯具）**:

```
成品: HJ-{品类}-{功率}-{客户简码}-{序号}   例: HJ-FL-100-354-001
结构件: 2.x.x.xxx  （沿用企业现有段码亦可，PLM 只强制唯一与校验规则可配置）
```

### 4.2 项目 NPI `plm_project`

中小灯企 **必须有轻量项目对象**（对应 EBMS 项目经营，PLM 存工程侧）:

| 字段 | 说明 |
|------|------|
| project_no | 与 EBMS 同源或 EBMS 生成回写 |
| part_no | 主产品 |
| customer_code、sales_owner、rd_owner | 责任 |
| phase、gate_status | 阶段与门禁 |
| target_mp_date、risk_level | 计划与风险 |

阶段门（灯具默认）:

```
G0概念 → G1方案 → G2结构冻结 → G3开模 → G4 T0/T1 → G5 T2/工试 → G6技转 → G7量产 → G8关闭
```

### 4.3 BOM 体系

| 类型 | 代号 | 用途 | 权威 |
|------|------|------|------|
| 设计 BOM | **EBOM** | 结构/3D 提取与维护 | PLM |
| 制造 BOM | **MBOM** | 工序、合并紧固件、生产发料 | PLM |
| 售后 BOM | **SBOM** | A/B/C 备件分级、手册 | PLM |
| 成本视图 | **CBOM** | EBOM/MBOM × 单价费率，只读计算 | PLM 计算，EBMS 消费 |
| 订单差异 | **OBOM** | 客户订单相对基线的 delta | EBMS 为主，PLM 可存变体引用 |

表: `plm_bom` + `plm_bom_item`(ltree path) + `plm_bom_version`(JSONB 强制)。

### 4.4 变更

```
ECR(问题/需求) → 评估影响 → ECN(方案+审批) → EFFECT → 快照/升版/作废旧版/通知EBMS
```

`plm_ecn_impact`: PART / BOM / FILE / MOLD / SOP / TRADE_DOC / ORDER_HINT  

审批默认（可配）: 工程师提交 → 研发主管 L1 → 供应链/工程 L2 → 生效岗 effect。

### 4.5 文档档案（灯具 固定树，禁止随意建文件夹）

在原 17 节点思路上固化为 **灯具标准档案包**（二级节点约 20–30 个）:

```
01 需求与配置    02 外观评审     03 结构3D/2D
04 光学/配光     05 电控/安规    06 模流分析
07 模具3D拆模    08 模具加工图   09 试模报告
10 工艺SOP       11 检验标准     12 产品BOM
13 ECN包         14 包材/标签    15 外协图纸包
16 客户确认/规格书 17 量产放行包  18 售后备件
```

文件: 版本号、doc_state、内外网、水印、禁止物理删除。

### 4.6 模具 / 工艺 / 品质 / 外协 / 贸易

| 域 | 核心对象 |
|----|----------|
| 模具 | 资产台账、型腔、啤数、状态、试模履历、关联 part_no |
| 工艺 | SOP 步骤卡、DFM 检查单、注塑参数卡 |
| 品质 | IQC/IPQC/FQC 标准（尺寸/外观/装配/功能/防水/来料） |
| 外协 | 发图申请、审批、水印包、有效期、下载审计 |
| 贸易 | 中英手册任务、3D PDF/爆炸图、电商白底、装箱测算、分享 Token |
| 3D | 模型库、爆炸任务 Job、LED 模板库 |

## 5. 统一生命周期（完整状态机）

### 5.1 对象主状态 `lifecycle_state`

```
                    ┌──────────────┐
          ┌────────►│  IN_REVIEW   │────────┐
          │         └──────────────┘        │
          │                                 ▼
┌─────────┴─┐                         ┌───────────┐       ┌────────────────┐
│   DRAFT   │────────────────────────►│ RELEASED  │──────►│ IN_PRODUCTION  │
└───────────┘     (可跳过评审的简单件)  └─────┬─────┘       └────────┬───────┘
                                            │                      │
                                      ECN开始│                      │
                                            ▼                      │
                                      ┌───────────┐                │
                                      │ CHANGING  │◄───────────────┘
                                      └─────┬─────┘
                                            │ ECN生效
                                            ▼
                                      RELEASED / IN_PRODUCTION
                                            │
                                            ▼
                                      ┌───────────┐     ┌─────────┐
                                      │ OBSOLETE  │────►│ SEALED  │
                                      └───────────┘     └─────────┘
```

适用于: Part、Bom、关键 File、Sop、InspectionStandard（子集可裁剪）。

### 5.2 转换引擎（必建）

`plm_lifecycle_transition`: from, to, action, roles, guards(JSON), effects(JSON)  

**关键副作用**:

| 动作 | 副作用 |
|------|--------|
| release | 锁编辑、写 version 快照、校验门禁 |
| start_change | Part→CHANGING（ECN 提交时） |
| ecn_effect | version++ **落库**、快照、旧文件 obsolete+水印任务、BOM 升版、发 Outbox 事件 |
| to_mp | phase=MASS_PRODUCTION，通知 EBMS 可大货 |
| obsolete | where-used 检查、禁止新订单映射 |

### 5.3 发布门禁（灯具默认包）

| 对象 | 门禁项 |
|------|--------|
| 成品 Part 发布 | 中英名称、关键灯具参数、至少 1 份结构文件或 3D、EBOM 无环 |
| 量产 IN_PRODUCTION | 技转包完成、IQC/IPQC 标准 RELEASED、关键模具非未验收（可配） |
| EBOM 发布 | 数量>0、无禁用关键件、cycle check |
| 外协包 | 仅 RELEASED 文件、水印模板、有效期 |

## 7. 端到端业务场景（灯具）

### S1 新品（客户定制投光灯）

```
销售询价 → EBMS 配置表
  → 立项(EBMS) → PLM 建 Project + Part(DRAFT) + 档案树
  → 结构3D/爆炸 → 提取 EBOM → 设计评审 IN_REVIEW → RELEASED
  → 开模(MOLD_DEV) → 试模履历 TRIAL → SOP/检验标准
  → 技转包 → G6 放行 → IN_PRODUCTION
  → EBMS 可大货接单；订单映射 Part + 锁 version
  → CBOM → 订单分析计划毛利 → 经营审核
```

### S2 改版（客户改光学/结构）

```
ECR → ECN(L1/L2) → 设计改 EBOM
  → effect: 版本 V1.1、旧图作废水印、SBOM/手册刷新任务
  → Webhook → EBMS 打开订单「成本待重算」
  → 未交付订单评估是否切版
```

### S3 外协开模件

```
选 RELEASED 模具图 → 外协申请 → 审批 → 水印包
  → 供应商下载审计 → 过期失效
```

### S4 外贸出货资料

```
SBOM + 规格书 + 爆炸图 + 装箱数据
  → 贸易任务包 → 客户分享链接（脱敏3D）
```

### S5 售后换件

```
SBOM A/B/C → 报价/发货（EBMS/ERP）
  → 仅 RELEASED 且非 OBSOLETE 件
```

## 12. 实施路线图（建议 9–12 个月）

> 按管理价值排序；每阶段结束可停可宣讲。

### Wave 0｜地基（4–6 周）

- 统一 Part 模型与 lifecycle 引擎  
- 修复/重做 ECN 生效落库与快照  
- 用户角色、审计、Docker 一键  
- **验收**: 状态机单测 + 升版 DB 可查  

### Wave 1｜主数据 + 档案 + 产品库（6 周）

- 产品档案/物料库/导入  
- 灯具档案树自动生成  
- 文件上传与权限  
- **验收**: 新料号 10 分钟建档完成  

### Wave 2｜BOM + 成本视图 + EBMS 映射（6–8 周）

- 树 BOM + EBOM 发布  
- CBOM API  
- EBMS 订单映射校验 PLM 状态  
- **验收**: 订单分析可拉正式结构算计划毛利  

### Wave 3｜变更闭环 + 项目阶段（6 周）

- ECR/ECN 完整 + 影响面  
- 项目 G0–G8 与 EBMS 项目号  
- ECN→EBMS 重算事件  
- **验收**: 改一处结构，版本/旧图/订单待办全自动  

### Wave 4｜3D 爆炸 + 模具 + 工艺品质（8 周）

- Web3D/模板/Job  
- 模具台账试模  
- SOP/DFM/检验标准  
- **验收**: T1 前资料包齐全可检查  

### Wave 5｜外协安全 + 贸易输出（6 周）

- 外协水印全链路  
- 规格/装箱/分享  
- **验收**: 外协零原版、客户链接可追踪  

### Wave 6｜ERP 与深化（持续）

- 料号/MBOM 推 ERP

## 16. 总结

面向 **100–300 人、0.5–2 亿销售额、工贸一体灯具制造** 的完整 PLM，不是「大而全抄 Teamcenter」，而是：

1. **工程侧**: 料号、版本、状态机、BOM 三态、ECN、档案水印、模具工艺、3D 爆炸——**一套真相**；  
2. **经营侧**: 通过 CBOM 与事件和 EBMS 订单分析、项目进度严密咬合——**可算账、可跟进**；  
3. **贸易侧**: 规格/备件/装箱/脱敏分享——**出得去、控得住**；  
4. **实施侧**: 模块化单体 + 6 波交付 + 行业模板——**IT 少也能上线**。

本说明书作为建设基线；详细表结构与接口可在 Wave 0 拆解为 `database/ddl` 与 OpenAPI。

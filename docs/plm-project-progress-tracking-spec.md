## 一、背景与来源清单(sales 原系统全貌)

sales 的「研发中心-项目管理」含 7 个页签 + 1 个独立技转子系统, 清单如下:

| 页签 | 名称 | 核心内容 |
|------|------|----------|
| 1 | 项目(projects) | 项目主数据(编号/名称/客户/类型/等级/负责人/日期/金额/阶段/状态), 导入 |
| 2 | **进度跟踪(progress)** | **项目进度一览表**: 19 个跟踪节点矩阵, 单元格可填「完成/未完成/进行中/待定/计划日期/文字」 |
| 3 | 供应链品质异常(supply) | 15 字段异常单(问题/措施/原因/责任/闭环) |
| 4 | 销售推广进度(sales) | 产品型号/业务员/客户/外观·价格·性能·功能反馈/进度 |
| 5 | 项目复盘(review) | 回顾目标→评估结果→分析原因→总结规律→行动计划, 含**自动复盘** |
| 6 | 立项申请(initiation) | 六大区块 + 五阶段审批(**PLM-2 已实现**) |
| 7 | 统计分析(analysis) | 月度/分类/交付周期/变更/延误 多维分析 |
| 独立 | 技转(tech-transfer) | 文档(版本/审核/批准/预览/下载/转发/复用)、流程(阶段/同步进度)、交接、变更、复盘、案例、密级、泄露告警、访问日志 |

### 进度节点(19 个, 从「计划表」开始)

`计划表 → BOM → 规格书 → 配置表 → 模具图纸 → 开模评审 → 手样 → 模具 → 模样 → 包装设计 → 电试 → 研试 → 工试 → 生试 → 测试报告 → 技转 → 出货 → 复盘 → 其他`

### 原系统节点单元格语义与筛选标准

- 单元格值: `V`(完成) / `X`(未完成) / `进行中` / `待定` / `日期`(计划完成日期) / 自由文字
- 列筛选: 已完成 / 有计划日期 / 进行中–待定 / 有文字备注 / 未设置
- 项目级节点筛选: 有进行中节点 / 有计划日期 / 有未设置节点 / **关键节点全完成**
- **关键节点**: 开模评审、模具、研试、工试、生试、测试报告、技转
- 节点变更计数(`node_edits`)→ 触发单元格颜色递进; 节点改动计入项目 `change_count`

## 二、目标与范围

**总目标**: 在 PLM-2「研发项目」模块内, 建成"**计划 → 节点执行 → 证据文件 → 检查 → 分析考核**"的闭环, 使每个进度节点的完成情况**可证明、可检查、可分析、可考核**。

**范围内(本期方案覆盖)**:
1. 19 节点进度跟踪(一览表矩阵 + 节点展开表单 + 证据文件)
2. 供应链品质异常、销售推广进度、项目复盘(含自动复盘)
3. 统计分析(月度/交付/变更/延误/对标)
4. 技转子系统(文档/流程/交接/变更/复盘/案例)
5. 导入导出(复用已建 `dataio` 引擎) + 自检

**范围外**: 财务成本核算、库存/ERP 实际出入库(仅预留接口)。

**与现有模块复用关系**:
- `plm_project`(研发项目)、`plm_project_gate_log`(阶段门 G0–G8) — 进度节点与之对齐
- `plm_process_route/step`(工序流转) — 试产/技转节点可自动生成工序待办
- `plm_ecn`(变更)、`plm_mold`(模具台账)、`plm_bom`(BOM)、`plm_archive_file`(档案)、`plm_model3d`
- `dataio` 通用导入导出/自检、`dq` 数据治理、`file` 文件服务、`log` 操作日志

## 三、总体设计

### 3.1 分层

```
研发项目(plm_project)
  ├─ 阶段门 G0–G8 (已有)
  ├─ 立项申请 (已实现)
  ├─ 进度跟踪  ──► 19 节点(node) × 证据文件(evidence)   ← 本方案核心
  ├─ 供应链异常 / 销售推广 / 项目复盘
  └─ 统计分析
技转子系统 (独立于项目, 通过 project_id 关联)
  ├─ 技转文档(版本/审核/批准/密级/泄露告警)
  ├─ 技转流程(阶段推进, 可回写进度节点)
  ├─ 交接单 / 变更单 / 复盘 / 案例库
```

### 3.2 关键设计决策

| 决策 | 方案 | 理由 |
|------|------|------|
| 节点存储 | **规范化**(每项目 19 行 `plm_project_node`), 不再用"一项目一行 19 列" | 支持展开表单、附件、审计、逐节点责任人与日期、可查询分析 |
| 节点值 | 由"单元格混合值"升级为结构化: `status` + `plan_date` + `actual_date` + `remark` | 提供可证明/可考核的数据 |
| 完成证明 | 节点完成必须 `status=DONE` **且** `actual_date` 非空 **且** 至少有 1 个证据文件 | 直接满足"证明完成情况" |
| 关键节点 | `is_key=true`(7 个: 开模评审/模具/研试/工试/生试/测试报告/技转) | 对标与考核聚焦 |
| 文件 | 复用 `file` 服务(内外网隔离/水印/日志), 证据仅存 file_id 引用 | 不重复造轮子 |
| 自检 | 复用 `dataio` 引擎 + 项目专属规则 | 统一入口 |
| 分析 | 指标口径与公式在本文档冻结(见 4.7) | "定标准" |

### 3.3 评审已确认(标准冻结)

| 事项 | 决议 |
|------|------|
| 完成硬标准 | ✅ **采纳**: 完成 = 状态 DONE + 实际日期 + 证据文件≥1(强制上传) |
| 本期范围 | ✅ **P1–P3**: 进度节点跟踪 + 供应链异常/销售推广/项目复盘 + 统计分析 |
| 关键节点验收 | ✅ **走审批**: 关键节点置 DONE 需研发主管/总经理验收通过, 审核链留痕 |
| 证据归档 | ✅ **自动同步归档**: 关键节点证据自动写入物料 17 层档案目录对应节点 |
| 节点范围 | ⏳ 未明确 → **默认启用全部 19 节点**(关键 7 用 ★ 标记单独考核), 如需精简可调整 |
| 健康分权重 | ⏳ 未提出异议 → 按 4.7 执行(0.35/0.25/0.20/0.10/0.10) |

**受此影响的标准调整**:
- 4.2 状态机: 关键节点 DONE 前置 `approval_status=APPROVED`(研发主管一审 → 总经理二审); 未验收通过不得置 DONE
- 4.9 权限: 新增"关键节点验收"动作(研发主管/总经理)
- P1 验收: 增加"关键节点验收审批链"用例

### 4.2 节点状态与状态机标准

```
NOT_SET(未设置) ──设计划日期──► PLANNED(已计划)
      │                              │
      │                              ▼
      └──────────────────────► IN_PROGRESS(进行中)
                                     │
              ┌──────────────────────┼──────────────────────┐
              ▼                      ▼                      ▼
           DONE(已完成)          FAILED(未完成)        PENDING(待定)
```
- 允许回退: DONE → IN_PROGRESS(需填原因, 记审计)
- **完成判定(硬标准)**: `status=DONE` **且** `actual_date` 非空 **且** 证据文件数 ≥ 1; 三者缺一, 自检标记 `HIGH: 完成证据不足`
- 逾期判定: `plan_date < today` 且 `status ∉ {DONE}` → 逾期
- 计划准确: `actual_date ≤ plan_date`(已完成节点)

### 4.6 自检规则标准(可证明性检查)

| 规则 | 级别 | 判定 |
|------|:----:|------|
| 完成证据不足 | HIGH | status=DONE 但缺 actual_date 或 证据文件 |
| 关键节点未闭环 | HIGH | is_key 且 status≠DONE(项目未关闭时) |
| 逾期未完成 | HIGH | plan_date<today 且 status∉DONE |
| 节点未设置 | MEDIUM | status=NOT_SET |
| 日期倒挂 | MEDIUM | actual_date<plan_date 的前序节点/或早于项目 start_date |
| 计划缺失 | MEDIUM | 关键节点 plan_date 为空 |
| 字段完整率低 | MEDIUM | 节点字段完整率 < 80% |
| 异常未闭环 | MEDIUM | 供应链异常 closed=0 且超期 |
| 文件命名不规范 | LOW | 证据文件名不符合命名规范 |
| 复盘缺失 | LOW | 项目状态=completed 但无复盘记录 |

自检输出: 每个项目的**健康分 + 节点完成率 + 问题清单**(复用 `dataio` 自检面板风格, 支持导出)。

### 4.7 分析与考核标准(指标口径 + 公式, 冻结)

> 设节点总数 `N=19`, 已完成节点数 `D`(status=DONE), 关键节点数 `K`(7)、关键已完成 `KD`,
> 已完成节点中 `actual_date ≤ plan_date` 的数量 `OT`, 有实际日期的已完成节点数 `DC`,
> 项目变更次数 `C`(change_count), 字段应填数 `F`、已填 `FF`。

| 指标 | 公式 | 基准/阈值 |
|------|------|-----------|
| 节点完成率 NCR | D / N | ≥80% 优, 60–79% 中, <60% 差 |
| 关键节点完成率 KCR | KD / K | ≥90% 优, <70% 预警 |
| 计划准时率 OTR | OT / DC | ≥85% 优 |
| 数据完整率 CR | FF / F | ≥90% 优 |
| 变更系数 CF | max(0, 1 − C/10) | C=0 → 1.0; C≥10 → 0 |
| **项目健康分 HS** | **100 × (0.35·NCR + 0.25·KCR + 0.20·OTR + 0.10·CR + 0.10·CF)** | ≥85 优 / 70–84 良 / 60–69 中 / <60 差(预警) |
| 交付周期 | close_date − start_date(缺则 target_date − start_date) | 基准 180 天 |
| 逾期项目数 | target_date<today 且 status∉{completed} | 0 为佳 |

**分析视图标准**:
1. 月度分析: 每月立项数/进行中/自研·客制/客户数/有订单数
2. 分类分析: 按类型 / 按阶段 / 按负责人
3. 交付与变更: 平均/最长周期、完整率、变更总数、Top 变更项目
4. 进度对标: 按类型/负责人对比 变更次数、延误节点数、逾期数
5. 延误分析: 按月/季/年 + 明细 + 责任人/类型分布
6. 自动复盘: 依据 NCR/KCR/OTR/C/逾期/订单 自动生成 亮点/不足/成功因素/失败原因/规律/行动计划(规则引擎, 标准见 4.7 阈值)

### 4.8 界面/交互标准

| 界面 | 说明 | 对应 sales |
|------|------|-----------|
| 进度一览表 | 项目 × 19 节点矩阵; 单元格着色(完成绿/进行中橙/逾期红/未设置灰); 列排序+按值筛选; 项目级节点状态筛选 | Tab2 |
| 节点展开表单 | 点单元格 → 抽屉展示该节点**完整表单 + 证据文件列表(上传/预览/下载/版本)** | 原系统仅弹窗, **本方案增强** |
| 时间线/甘特 | 计划 vs 实际(按节点日期) | 新增 |
| 项目档案卡 | 项目主数据 + 进度矩阵 + 异常 + 推广 + 复盘 汇总页 | 新增 |
| 检查分析面板 | 健康分仪表盘 + 指标卡 + 问题清单 + 导出 | 新增(结合 dataio) |
| 导入导出 | 复用 `dataio`(进度节点、异常、推广、复盘模板) | Tab2 导入进度 |

交互标准: 单元格状态变更/日期变更均写审计(`plm_entity_history` 或专用节点历史), 节点改动累加 `change_count`, 颜色按编辑次数递进。

### 4.9 权限标准(阶段与角色)

| 动作 | 允许角色 |
|------|----------|
| 查看进度 | 全部(品质/生产只读) |
| 维护节点(计划/日期/状态/证据) | 项目经理、研发工程师、系统管理员 |
| 验收关键节点(开模评审/技转等) | 研发主管、系统管理员 |
| 技转文档审核/批准 | 部门/总经理(技转独立权限) |
| 删除 | 系统管理员 |

## 七、实施分期与验收标准
